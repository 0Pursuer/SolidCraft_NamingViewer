# SolidCraft 建模过程档案

独立的 Windows 本机记录器与浏览器查看器。使用已安装的 SolidCraft 及其 CLI，无需编译或替换 SolidCraft，也不修改原有 `topology-live` 程序。

## 事务与状态流

首页现为流式操作展示：上方按 **已观察的 Undo 操作 → 当前位置 → 已撤销的 Redo 操作** 排列，点击节点，下方按 **操作组 → 特征 → 属性** 展开真实字段变化。右侧可切换变更前后数据；图形仅为包围盒示意，完整带面标签网格仍在“原始档案”中。

例如本次真实实验会显示：**创建草图 → 绘制矩形 → 创建拉伸20 mm → 当前20 mm → 修改高度20→40 mm（已撤销）**。进入编辑器的临时回退和最终提交可以合并为一个有观察证据的操作组，并保留 O0010/O0011 原始记录。

这些操作名称、分组和 Undo/Redo 关联都由文档差异与原生栈深度推断，不能当作原生事务调用树。已有但未采集的历史、断线、未完成快照及记录器会话边界会显示未知提示。页面点击只改变查看内容，不会执行 CAD Undo/Redo。

双击 `start-flow-viewer.cmd` 可读取 `records` 中最近更新的档案，不重启或接管正在运行的记录器；可用 `--archive <目录>` 指定档案。它以独立服务只读观察原档案，不向原档案创建记录或阶段重建任务；重算页面可提交独立 CLI 实验，结果另存于 `recompute-runs/`。`start-transaction-viewer.cmd` 继续负责连接实例并持续记录，首页也使用流程视图。

原有 JSON、历史网格和阶段重建页面保留在 `/archive`。从流程节点进入“原始档案”会直接定位对应的 O 记录。

## 启动

1. 在自己的 Windows 账号中启动 SolidCraft，开启本机 AI 控制通道。
2. 双击 `start-transaction-viewer.cmd`，选择要观察的实例。
3. 保持启动窗口运行，在 SolidCraft 中建模。网页会显示观察记录及保存状态。

本机已有 `records/verified-demo` 测试档案时，也可双击 `start-demo-viewer.cmd` 离线查看。该档案不随源码仓库提供；`records/` 整体由 Git 忽略。具体演示内容与验证边界见 [VERIFICATION.md](VERIFICATION.md)。

需要 Python 3.10 或更新版本。启动脚本会寻找 `py -3`、`python` 或系统安装的 Python 3.12。运行记录器仅使用 Python 标准库，网页没有第三方网络依赖。

网页端口默认由系统分配。启动窗口会打印本次地址和独立档案目录，默认保存到程序目录下的 `records/<时间>-<随机后缀>`。关闭网页不停止记录；在启动窗口按 Ctrl+C 停止。正常退出会关闭本程序创建的连接和子进程。

命令行示例：

```powershell
py -3 .\server.py --open
py -3 .\server.py --list-instances
py -3 .\server.py --control-port 27879 --archive 'E:\solidcraft\transaction-live\records\my-design' --open
```

`--control-port` 选择 SolidCraft 原生控制端口；`--port` 指定网页端口。默认只发现当前 Windows 用户的控制目录；可用 `--control-dir` 指定自定义目录。

现场软件版本从所选运行实例的原生 `ui.help` 取得，与离线 CLI 版本分别记录和显示；无法取得时标记未知，不用安装目录版本冒充现场版本。离线重建会记录实际启动 CLI 报告的版本，并提示与观察版本的差异。

## 页面怎么看

左侧 **O0001、O0002…** 是本档案的观察编号，不是 SolidCraft 原生事务ID，也不保证一条编号等于一次用户点击。选择观察后，可以查看：

- **历史几何**：当时取得的实体、面/边原始命名与显示网格。只剩草图时，可绘制具有原生 world 点坐标的直线；未绘制的圆、弧和样条会明确提示，完整数据仍可查阅。
- **变化对比**：已保存文档之间的字段差异。Feature ID 与时间线位置分开显示；“可能为 Undo / Redo”等操作类型始终标为推断。
- **Undo / Redo**：原生接口公开的栈深度。栈条目、Snapshot 的 before 文档、准确执行命令和原进程内部 ModelState 无法通过这些公开接口取得，因此明确显示不可获取。
- **特征时间线**：查看特征ID、定义与结果；选择前缀数量，按需提交离线重建。
- **原始数据**：查看或下载保存的 JSON、带面标签3MF等资源，也可下载完整 ZIP 档案。

取消“跟随最新观察”后，可停留在已有记录继续检查；记录器仍在后台持续采集。网页缓存最多5000条事件；更早的观察可用“观察编号”输入框直接跳转，完整记录以磁盘档案为准。

会话和阶段任务列表默认最多返回1000项，页面列表不等于完整档案的全部记录。原始资源与完整元数据仍保存在磁盘档案中。

## 离线阶段 S

例如 **O0008/S3** 表示使用 O0008 保存的文档定义，独立执行其前3个特征。`S0` 是空前缀，`S3` 不是 Feature ID 3。

重建调用已安装的 `solidcraft-cli.exe`，在独立工作目录运行，不向正在编辑的 CAD 实例发送 `timeline.roll_to`，不修改原文档。一次仅运行一个阶段任务；页面显示排队、运行、成功、失败、取消和超时状态。可使用 `--cli` 指定 CLI 路径，`--rebuild-timeout` 调整单个任务超时秒数，默认120秒。

**重建结果不是原进程当时保存的 ModelState。** 页面单独标为 S，记录输入文档哈希、CLI版本及告警，原生 Undo / Redo 深度不适用。依赖资源缺失、外部链接无法独立解析、版本差异或特征求值失败时，不会把不完整结果称作成功还原。

失败、取消或超时任务仍显示诊断；如果任务在停止前已取得部分原始数据，任务卡片提供这些资源的下载链接。任务保持未完成状态，不会将部分文件包装成一个成功的 S 阶段。

CLI 工作进程有超时和取消终止机制，但没有操作系统级 RSS 内存硬上限。复杂模型可能在超时前使用较多CPU或内存。

## 连续性与容量

记录器订阅所选实例的原生文档变更通知，使用独立查询连接取得公共数据。每次采集前后核对文档身份和revision；更新过快时，通知可以被记录，但对应中间几何可能已经无法查询。此时保存缺口或未采集状态，不把后来的几何冒充早先状态。断线、订阅中断与重启也会保留可见诊断。

采集与浏览器轮询独立。关闭网页不会停止记录；页面“暂停记录”停止后续采集，不等于暂停 SolidCraft。重新连接只允许原来选定的启动实例；实例退出或同端口被新实例替代时，需要重启记录器重新选择。

档案默认应用配额 **2 GiB**，包含数据库、对象与本程序临时资源，可用 `--limit-gib 2` 显式指定。采集前预留192 MiB工作空间，重建前预留256 MiB，因此剩余容量不足预留空间时可能提前暂停或拒绝任务，已有档案保留，不自动删除旧观察。

该配额是应用层容量预算，不是操作系统的硬盘硬限额；原生导出过程可能短暂超过预期空间，无法保证磁盘使用始终严格不越界。需要继续记录时，停止当前记录器，使用新的档案目录启动或明确调整预算；不要手动删除正在使用的 SQLite/WAL 或对象文件。

## 重新打开档案

```powershell
# 离线浏览，可使用本机 CLI 按需新增重建阶段
py -3 .\server.py --offline --archive 'E:\solidcraft\transaction-live\records\my-design' --open

# 严格只读，不记录、不重建、不创建ZIP打包临时文件
py -3 .\server.py --read-only --archive 'E:\solidcraft\transaction-live\records\my-design' --open
```

档案使用 SQLite 保存事件、观察、任务与阶段元数据，资源文件按 SHA-256 哈希去重保存。网页通过资源哈希读取已保存内容；没有任意文件读取或通用 CAD 命令接口。下载 ZIP 用于保存和分享完整档案；再次浏览时先解压到独立目录，再指定 `--archive`。

严格只读模式下可查看和下载已有单个资源，完整 ZIP 下载被禁用，以免写入打包临时文件。需要备份时直接复制已停止写入的档案目录，或在普通离线模式使用“下载完整档案”。

HTTP 仅监听 `127.0.0.1`，使用同源cookie与来源检查；CAD控制token不进入浏览器或档案。本机端口不提供 Windows 用户身份隔离，知道地址的其他本机用户仍可能访问。档案包含设计定义、几何与参数，请按模型文件本身的保密要求管理。

## 显示数据的含义

面/边完整名称来自原生查询，`exact` 是 SolidCraft 的历史来源状态，不保证任意编辑后永久不变。面使用原生面标签对应网格；边曲线依靠标签边界与原生采样证据重建，无法唯一对应时保留原始目录并隐藏该具名曲线。P编号是查看器去重生成的展示点，不是独立持久顶点名称。

显示与采集有实体数量、数据大小和工作量预算。超限、资源缺失和无法解析的几何均以告警表示；完整公共数据与部分几何结果在页面区分。

## 开发与验证

`viewer.html` 是中文档案界面，`geometry.html` 是离线消息驱动的渲染框架。父页面仅通过同源 `trace-geometry` 消息发送已保存数据；几何页不发起CAD或HTTP轮询。

```powershell
py -3 -m unittest discover -p 'test_*.py' -v
node --test test_ui.js

# 可选：使用已经安装的 Python Playwright 和 Chromium 运行浏览器fixture测试
py -3 -m unittest test_ui_browser -v
```

浏览器fixture测试只连接其自己创建的临时本机测试服务器，不连接SolidCraft。它覆盖观察选择、阶段重建界面、草图线框、原始数据安全渲染及手机布局，截图写入本目录。`TRACE_UI_BROWSER` 可指定已有 Chromium/Chrome 可执行文件。

默认测试不读取个人现场档案。原验收样例的可选只读浏览器检查，只有显式设置 `TRACE_REAL_ARCHIVE` 指向对应档案时才启用；干净检出不需要这些运行数据。

`build_geometry.py` 仅用于开发时从仓库内相邻的 `topology-live/live-viewer.html` 适配渲染器，输出本目录的 `geometry.html`；最终交付已包含生成产物，正常运行不需要原程序目录。


重算机制演示：启动 start-flow-viewer.cmd 后点击「重算演示」。源码流程与独立 CLI 实测分开显示，说明与边界见 [RECOMPUTE-VERIFICATION.md](RECOMPUTE-VERIFICATION.md)。

该页面的「Session · Document · Model · Snapshot」区域提供对象关系和修改/Undo 调用演示，见 [LIFECYCLE-VERIFICATION.md](LIFECYCLE-VERIFICATION.md)。源码步骤不等于函数级运行 trace；只有通过校验的已保存阶段和匹配本次修改的原生命令回复标为实测。浏览和关联实验只读取数据。

`test_lifecycle_real.py` 会在临时目录创建原生样例，用独立无界面 CLI 完成 20 → 40 → Undo，再通过本地测试服务验证网页。它不连接桌面实例，也不依赖个人档案或固定实验编号；未安装 CLI 或 Playwright 时明确跳过。
